# lcsc-part-params

**不申请 API 密钥，从立创商城的公开页面直接拿物料参数。**

给一颗立创编号（或型号），拿回：

型号 · 品名 · 品牌 · 封装 · 分类 · 最小包装 · **数据手册地址** · **完整参数表**

面向「自己搭 BOM / 元器件库存系统」的场景：**不申请开发者密钥、不模拟登录、不绕过任何访问控制**。

## 用法

Node 18+，**零依赖**：

```bash
node lcsc.mjs C42411897          # 立创编号
node lcsc.mjs RTL8189FTV         # 型号（自动先查编号）
node lcsc.mjs C42411897 C25804   # 一次多个
```

输出：

```json
{
  "编号": "C42411897",
  "品名": "2.4GHz 无线模块",
  "型号": "E103-RTL8189FTV",
  "品牌": "EBYTE（亿佰特）",
  "封装": "SMD，12×12mm",
  "分类": "WiFi 模块",
  "最小包装": "1000圆盘",
  "数据手册": "https://atta.szlcsc.com/…pdf",
  "参数": ["核心芯片=RTL8189FTV-VC-CG", "支持协议=IEEE802.11b/g/n", "…"]
}
```

## 数据从哪来（都不用登录）

| 想要什么 | 从哪儿来 |
| --- | --- |
| 型号 → 立创编号 | 立创EDA 公开搜索 `easyeda.com/api/eda/product/search` |
| 编号 → 商品 ID | 立创EDA 公开详情 `easyeda.com/api/products/<编号>/components` |
| 参数 / 封装 / 规格书 | 立创商城商品页里自带的 `__NEXT_DATA__` |

关键：商城的商品页是**为了被搜索引擎收录、提前在服务端拼好的** —— 名称、品牌、参数表、图片、规格书地址，在页面打开之前就已经整块写进了 HTML。属于页面自带的公开内容。

## 两个坑（我踩过，你可以直接跳过）

1. **商品 ID ≠ 立创编号** —— 想当然拿编号拼商品页地址会 404。正确顺序：先问立创EDA，从返回里取**真正的商品 ID**，再打开商品页。
2. **规格书地址是「半截」的** —— 页面里存的是 `/upload/public/pdf/…`，直接拼主站域名返回的是**网页**不是 PDF。真正能下到文件的是 **`atta.szlcsc.com`**。

## 有两类我**没有**抓（说清楚，省得你白试）

**立创工业品（MRO）** 与 **嘉立创机械商城**：抓不到，两个原因都不在你这边 ——

1. 这类链接会被**转站**：工业品单独放在 MRO 频道，普通商品地址打开会 302 跳到 `/mro/`；
2. 外面套了一层**人机校验**：返回的是一张 WAF 的 JS 校验页（`acw_sc__v2` 脚本），要浏览器跑一遍拿凭据再请求 —— **服务端拿不到**，UA 伪装全了也一样。

我的处理：这两类**老实手填**；图片可以「借」（页面上右键复制图片地址）；真要自动化就走官方接口（JOP）。

**我没有去绕那层校验，也不建议绕** —— 一是对方随时可以改，二是「绕过访问控制」与「遵守对方用户协议与 robots、不绕过访问控制」是冲突的。本仓库这套思路对**普通电子元件**（商城里的标准商品）是通用的。

## 让它长期稳定地跑

- **缓存**：同一个编号的结果存起来（原实现按 90 天）
- **限速**：批量识别时排队 + 留间隔，别把人家页面刷爆
- **优雅失败**：页面结构万一变了，要能「识别失败就留空、手填」，不要整批崩掉
